Mesh up/down bitrate on the Packets graph

Record mesh up/down throughput (bits/s) in each history sample, using the same babel neighbor interfaces as the TX/RX packet counts, and draw it in a stacked lower panel on the Packets graph that shares the time axis.

Data flow

sysfs tx_bytes/rx_bytes per mesh dev→ sample.uc byte Δ × 8 / dt→ store.uc slots 39, 40→ sync/series: net_tx_bps, net_rx_bps→ Packets: bottom panel

Daemon / storage

  • readDevCounters(dev) also reads statistics/tx_bytes and rx_bytes.
  • The existing per-device delta loop sums byte deltas alongside packet deltas, so the bitrate covers the same babel neighbor devices (RF, DtD, XLink, WG).
  • store.last.dev_t holds the previous sample time; net_*_bps = int(bytes_delta * 8 / dt), 0 on the first sample.
  • store.uc writes/expands b[o + 39] / b[o + 40]; RF/link/cost blocks shift automatically via SAMPLE_HDR. Ring is RAM-only, so no migration.
  • RAM cost: two ints per slot, about +34 KB at 4h and +207 KB at 24h.

UI

  • METRICS.links gains stackedPanels: true, topPlotH: 140, and bottom-panel series up (net_tx_bps) and down (net_rx_bps).
  • drawChart uses metric.stackedPanels for any metric; the UNREACH band stays cost-only.
  • fmtBitrate (b/s, kb/s, Mb/s, Gb/s, base 1000) in tooltips and KPIs; compact fmtBitrateAxis (500k, 2M) for the Y-axis gutter through drawAxes opts.fmtY.
  • Bottom-panel Y max rounds up to 1/2/5 × 10^n with a 1 kb/s floor.
  • KPI row adds Up and Down next to TX Δ / RX Δ.
