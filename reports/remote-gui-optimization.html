Problem (current behavior)

index.html refreshSeries() (~3001–3055) re-downloads the entire visible window every 10s tick and on every zoom/pan, as sequential 300s api=series slices (4h ≈ 48 requests; 24h ≈ 288). There is no sample cache (series = [] replaced wholesale). Metric tabs already redraw from the same array (no extra network). Server already has incremental api=sync&since_seq= for pollers and gzip; the chart never uses sync. Events always use since_seq=0.

tick_10s→ api_live + api_events_full + api_series_all_slices→ replace_series_array→ drawChart

Target behavior

tick_10s→ api_live + api_events_since_seq + ensureVisibleCached
ensure→ fetch_missing_slices_only→ clientSampleCache→ drawChart_from_window
ensure→ api_sync_since_maxSeq_if_live→ clientSampleCache
bgUpdate_idle⇢ fetch_older_slices→ clientSampleCache

Approach

Primary work is client-side in src/www/babel-monitor/index.html. Reuse existing APIs (series, sync, events, live). No new daemon endpoint required for the core path. Bump package version / README / packageVersion() when shipping.

1) Client sample cache (browser ring)

  • Keep a Map/object keyed by seq (plus ordered seq list) holding expanded samples already received.
  • Invalidate on boot_id change (from live/meta/series).
  • Cap to node sample_cap / retention: drop samples older than now − retentionSec (and below min_seq if advertised).
  • Derive display series = samples in the current minute-aligned view window from cache (do not replace cache on each draw).
  • Do not purge on zoom-in when Background update is off (keep what was fetched so zoom-out/pan into known areas is free). Background off only means do not actively fetch outside the visible window.

2) Fetch only what is missing + incremental tip

  • Visible window first: compute needed [t0, tEnd] (existing computeViewWindow). Diff against cache; fetch only uncovered ranges via api=series&seconds=&end_age= (still ≤300s per request).
  • Live edge (viewEndAgeSec === 0): after the window is covered, each tick uses api=sync&since_seq=<maxCachedSeq> to append new samples only; then drop aged-out samples from the client cache (mirror the node ring).
  • Panned / historical view: if the visible window is fully cached, skip series network on tick (still refresh live KPIs/events).
  • Zoom/pan into cached data: draw immediately from cache; only network for gaps.
  • Parallelism: issue missing slices with concurrency 3. Abort in-flight series work with AbortController when the user changes window or a newer ensure starts.
  • Merge/dedupe by seq into the cache.

3) Loading indicator

  • Animated spinner/icon in the header between <h1>babel-monitor</h1> and #setupBtn.
  • Show while any history ensure/gap-fill/sync-tip (or initial live) is in flight; hide when idle.
  • Prefer this over a black empty chart; keep drawing whatever cache already has (progressive reveal).

4) Background update control

  • Checkbox on the header top row (label Background update, unchecked by default), persisted in localStorage.
  • When on and UI is idle: slowly walk older 300s slices toward full retentionSec (one slice every ~2s, concurrency 1).
  • When off: only ensure the currently displayed window (plus live tip when live).

5) Sent/recv bandwidth (60s rolling)

  • Instrument getJson/fetch for request and response byte sizes.
  • 60s rolling sum of bytes sent (client→node) and recv (node→client).
  • Display to the right of Uptime as compact text like 10.3KB/104.1MB (sums over the last 60s).
  • Tooltip explains sent/recv and the rolling window.

6) Header metadata cleanup

  • Identity line: hostname · node_id · Uptime … then bandwidth; remove boot … and package version from the always-visible string.
  • Put boot_id and package version on the babel-monitor title title= tooltip.

7) Events incremental

  • Track last event seq and call api=events&since_seq=… (merge/cap list), instead of full since_seq=0&limit=80 every 10s.
